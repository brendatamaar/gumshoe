The problem

Agents work in the demo. Then they meet production.

The loop around the model usually isn't engineered like the rest of your stack. The same five failures show up every time, and teams patch them one library at a time. Gumshoe fixes all five with one mechanism.

01

Blocking loops

A while True loop holds a thread, can't serve concurrent traffic, and dies messily on the first error.

Async orchestrator: 100+ runs per worker on one event loop.
02

Untrusted outputs

Models hallucinate tool parameters. Raw LLM output should never touch a real API.

Typed tool router with self-healing retries.
03

Runaway cost

A loop that never converges keeps calling the model. It's an outage that arrives as an invoice.

Cost kill-switch: downgrade at a soft limit, halt at the cap.
04

Unchecked actions

Refunds, deletions and outbound messages run without sign-off. Generated code runs on the host.

Approval gate and an isolated sandbox executor.
05

Silent regressions

A prompt tweak changes which tools get called. You only grade the final text, so nobody notices.

Trajectory replay and a CI gate on every pull request.
How it works

One run state. One event log. Everything else for free.

Every agent run is a durable, typed state machine. Each transition is a versioned event in an append-only log. Guards, approvals, tracing, replay and the CI gate all read that same log, so none of them needs its own instrumentation.

(state₂, commands)=step(state₁, input) The core never does I/O. LLM calls and tool calls are commands the shell executes.
01 · Pure core

Deterministic by construction

No clock, no randomness, no network inside step. Time and ids arrive as data, so the same inputs always yield the same commands. Replay, shadow runs and pause/resume just work.

02 · Event log

The log is the source of truth

State is a fold over the log. A run resumes on any worker, survives a crash without duplicating a side effect, and replays offline exactly as it happened.

03 · One policy shape

Every guard is a function

evaluate(state, action) returns allow, deny, pause or downgrade. The kill-switch, sanitizer and approval gate share it, and so do yours.

Architecture

Five modules, one contract.

The runtime writes every transition through core. Guards plug into the same policy interface. The lab only reads the log, which is why replay and CI need no extra wiring.

Built on PostgreSQL with SKIP LOCKED, SQLite for local development. No Redis, no Kafka, no extra moving parts.

gumshoe.runtime

A hundred agents on one event loop. None of them blocking.

Submit runs over HTTP or the CLI. Workers claim them with leases, bound concurrency with backpressure, and survive crashes without running a refund twice.

  • Typed tool calls. Tools are Pydantic models. Every LLM output is validated before anything runs.
  • Self-healing retries. Up to three attempts, with the validation error fed back to the model.
  • Crash-safe. Idempotency keys on every command. Kill a worker mid-run and another one finishes it.

gumshoe.guard

Guardrails that act, not just observe.

Dashboards tell you an agent went rogue after the fact. Gumshoe's policies run inside every step, before a command leaves the core, and every decision is written to the log.

  • Cost kill-switch. Projects spend before each call, falls back to a cheaper model at the soft limit, halts at the hard cap.
  • Approval gate. High-stakes tools pause the run. It waits days, not threads, and resumes from its snapshot.
  • Sandbox and sanitizer. Generated code runs in gVisor or E2B with no egress. Injected instructions get flagged.

gumshoe.lab

Catch the regression before it merges.

Your prompt change still produces a nice answer. It also stopped verifying identity before issuing refunds. The CI gate replays recorded runs, compares every tool-call path against its golden DAG, and blocks the pull request.

  • Deterministic replay. LLM and tool calls are served from recordings. Fast, free, identical every time.
  • Tolerant diffs. Mark steps as reorderable or required, so the gate stays strict without crying wolf.
  • Any agent. Ingests any OpenTelemetry GenAI trace, not just Gumshoe runs. Shadow 5% of live traffic to a new topology.

The platform

Everything you need between the model and the world.

Adopt one module or all five. They share one contract, so each new piece makes the others more useful.

gumshoe.core

The shared contract

Plain, frozen data and one pure step function. Everything else in Gumshoe is built on these types, and the core never imports I/O, asyncio or the clock.

pip install gumshoe-core

Run state machine

v0.1

PENDING → RUNNING → PAUSED / SUCCEEDED / FAILED / HALTED, with every allowed and forbidden transition property-tested.

Versioned events

v0.1

Gapless per-run sequence, schema versions and upcasters, so old runs keep loading after you upgrade.

Policy interface

v0.1

One evaluate() shape for every guard. All policies run, the most restrictive verdict wins, every decision is logged.

OpenTelemetry tracer

v0.1

One span per transition with GenAI semantic conventions. Export over OTLP to Jaeger, Tempo, Langfuse, LangSmith or Arize.

Event store

v0.1

Append-only, with inbox and outbox in one transaction. SQLite in dev, PostgreSQL in production.

State snapshots

v0.4

Versioned snapshots let long runs load fast and resume cleanly across schema changes.

gumshoe.runtime

The execution engine

The thin, effectful shell around the pure core. It talks to providers, runs tools, holds leases and keeps the event loop free.

For developers

Bring your agent. Keep your code.

Gumshoe isn't another framework for writing reasoning logic. It's the production runtime around it: plain Python, Pydantic models and a few lines of configuration.

agent.pypolicies.py.github/workflows/agents.yml
from pydantic import BaseModel
from gumshoe import Runtime, ReActAgent, tool
from gumshoe.guard import KillSwitch, ApprovalGate

class Refund(BaseModel):
    order_id: str
    amount_usd: float

@tool(risk=["payments"], idempotent=True)
async def issue_refund(args: Refund) -> str:
    return await payments.refund(args.order_id, args.amount_usd)

agent = ReActAgent(model="claude-sonnet-5-5", tools=[lookup_order, issue_refund])

runtime = Runtime(
    store="postgresql://localhost/gumshoe",
    policies=[
        KillSwitch(max_cost_usd=0.50, fallback_model="claude-haiku-5-5"),
        ApprovalGate(risk=["payments"], via="slack", timeout="3d"),
    ],
)

run = await runtime.submit(agent, input="Refund order 4471, it arrived damaged")
print(run.status)  # RUNNING, then PAUSED until a human approves
from gumshoe.core import Policy, PolicyContext, ProposedAction
from gumshoe.core import Allow, Deny, Pause, Verdict

class NoWeekendDeploys(Policy):
    """Deploys on weekends need a human. Production writes never run in a dry run."""
    name = "no_weekend_deploys"

    def evaluate(self, ctx: PolicyContext, action: ProposedAction) -> Verdict:
        if action.tool == "deploy" and ctx.now.weekday() >= 5:
            return Pause("weekend deploy", approval="#release-captains")
        if "prod_write" in action.risk and ctx.config.dry_run:
            return Deny("dry run cannot write to production", halt=False)
        return Allow()

# Pure: no I/O, no clock reads (ctx.now arrives as data), no counters.
# Every verdict is written to the log as a PolicyEvaluated event,
# so replays and CI reproduce the exact same decisions.
runtime = Runtime(policies=[KillSwitch(), NoWeekendDeploys()])
name: agent-trajectories
on: pull_request

jobs:
  gate:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      - uses: actions/checkout@v4

      # Replays recorded runs, diffs tool-call paths against golden DAGs
      - uses: gumshoe-ai/ci-gate@v1
        with:
          trajectories: tests/trajectories/
          tolerance: reorderable      # required steps must still appear
          max-cost-delta: "10%"       # fail if a change gets pricier
          traces: otel                # works with any OTel GenAI trace

# Result: a check that blocks the merge and a PR comment
# showing which step changed and how the cost moved.

FAQ

Questions, investigated.

Can't find the answer? Open a discussion on GitHub. A human reads every one.

Is Gumshoe an agent framework?

No. You bring your own agent logic, prompts and tools, or an existing framework like LangGraph. Gumshoe is the production runtime around it: concurrency, validation, guards, durable state, tracing and replay.

Does it replace Langfuse, LangSmith or Arize?

No, it feeds them. Those tools observe; Gumshoe acts by halting, pausing and blocking. Every run exports as OpenTelemetry GenAI spans, so your existing dashboards keep working.

How is this different from Temporal or DBOS?

Those are general-purpose durable workflow engines. Gumshoe is agent-aware: it validates tool calls, caps spend per run, tracks loop depth and repeats, and diffs tool-call trajectories. Durable execution covers agent runs only, and that focus is the point.

Does the CI gate only work with Gumshoe runs?

No. The CI gate ingests any OpenTelemetry GenAI trace, so you can gate an agent built on any stack and adopt the runtime later, or never.

What happens when a worker crashes mid-run?

Its lease expires and another worker claims the run, rebuilds state by folding the event log, and drains the outbox. Commands carry deterministic ids that double as idempotency keys. A tool not marked idempotent is never re-executed automatically; the run fails with unsafe_resume for a human to review.

Where does my data live?

In your Postgres, when self-hosted. Use full capture for replayable runs, or metadata_only in production to store hashes, sizes and timings. A redaction hook runs before anything is appended, and secrets never enter state, commands or events.

What's the license?

Apache 2.0 for all open-source code. The hosted services are separate products. The core contract will never be paid: a contract has to be open to be trusted.
